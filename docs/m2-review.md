## Built

- Election-only RaftNode driven by Step/Tick through injected Transport, Clock,
  Storage, and Random interfaces.
- Durable term/self-vote before requests, durable grants before replies, log
  freshness checks, distinct-voter majorities, stale-message handling, heartbeat
  timers, step-downs, restart behavior, and fail-stop handling of storage errors.
- Deterministic three/five-node simulator with virtual time, stable queued
  delivery, drops, duplicates, delays/reordering, partitions, crashes/restarts,
  and failures before/after sync.
- Historical per-term leader safety, monotonic terms/votes, and node/durable-state
  agreement checked after every simulated event. Negative oracle tests prevent
  a silently ineffective safety checker.
- Seeded cold-start, crash re-election, partition chaos, healed recovery, and
  full-trace replay checks.
- M1 approval/CI link recorded. CI pins Ubuntu 24.04 and uses Node 24 actions
  (checkout v5, setup-python v6, upload-artifact v6); Windows initialization uses
  the native VS developer shell.

See [the design](election-simulator.md) for event definitions, fault schedules,
the connected-quorum liveness assumption, and election-only limitations.
The StateMachine interface and planned `std::map` implementation remain unchanged.

Both local builds run the same 10,000 simulator seeds, 0 through 9999, as well
as the existing codec corpus. They are 10,000 unique simulator scenarios, not
20,000 unique seeds. Every campaign step invokes the safety oracle. The
simulator replay compares the complete seed-42 trace from two debug runs and
one ASan run. CI runs debug/ASan on Windows and Ubuntu, plus Ubuntu TSan, lint,
and tidy. The implementation remains single-threaded.

Capture with `scripts/capture_m2.ps1` from a clean committed source tree.
It runs all local gates into an ignored staging directory, verifies the source
revision/tree are unchanged, then publishes `results/m2/`. Commit the results
separately without source changes. `scripts/summarize_m2.py` validates complete
successful CTest output, clean provenance, matching codec/simulator runs, all
election bounds, safety-check counts, and matching replay traces before producing
the summary. M1 evidence is retained unchanged.

## Acceptance gates

- [x] Leader elected within the specified 300-tick cold-start bound.
- [x] A different leader is elected in a higher term within 300 ticks after a crash.
- [x] Historical at-most-one-leader-per-term checked after every simulated step
  across 10,000 seeds with packet loss and partitions enabled.
- [x] Explicitly injected runtime dependencies; no direct socket/thread/time/RNG calls.
- [x] Failing seed reporting and exact replay command, with deterministic full traces.
- [x] Regression tests for storage ordering, restart votes, election timer rules,
  majority counting, partitions, and the safety oracle itself.
- [ ] Final local clean-source debug/ASan/tidy/evidence capture verified.
- [ ] All final-commit CI jobs green.
- [ ] Owner approval.

The unchecked gates describe status at the source commit. The results-only
commit and linked CI run provide final capture and CI evidence for review.
No simulator-discovered implementation defect or failing seed is claimed.
